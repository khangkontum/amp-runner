# Amp Runner for macOS

> my personal amp runner manager on mac. vibed with amp itself 30m after I saw this [announcement](https://ampcode.com/news/one-runner-is-now-enough). the rest of the readme and codebase is entirely generated by astra.

---

A native macOS app for managing one app-owned [Amp runner](https://ampcode.com/docs/cli/runners) and its project folders. Keeps registrations persistent, runs in the background, and provides a menu-bar shortcut to the manager.

## Get started

Requires **macOS 14+**, **Xcode 26+ / Swift 6** to build, and an installed Amp CLI with multi-directory support.

```sh
bash scripts/build-app.sh
open "dist/Amp Runner.app"
```

For regular use, move the complete app to `/Applications` before starting the runner. Builds are ad-hoc signed for local use, not notarized for distribution.

1. Run `amp login` in Terminal if needed. The app reuses Amp's sign-in and never stores an API key.
2. Add project folders using **+**, **⌘N**, or drag-and-drop. Ordinary folders and Git repositories both work.
3. Click the **play control** beside **Stopped**. Optionally enable **Start at login**.
4. Choose this runner and a project folder on ampcode.com. The initial runner ID is `amp-mac-…`.

## Everyday use

- **Start / stop:** use the circular control beside the runner status. Stopping asks for confirmation, can interrupt active threads, and disables start at login. Closing the window or quitting the manager leaves the runner running.
- **Projects:** search by name or full path; search ignores case and surrounding whitespace. Each row's menu lets you reveal, relocate, or remove a folder. Removing a folder does not delete its files. Hover over a status dot for details.
- **Runner Settings:** select System / Light / Dark appearance, change the Amp executable while stopped, or open logs. To rename the runner, stop it, edit **Runner ID**, save, and start again. IDs must be valid hostnames and are case-insensitive. Saved folders follow the new ID; existing threads are not migrated.
- **Zoom:** font and content sizing persist from 75% to 175%. Native window chrome, menus, alerts, and folder pickers retain system sizing.

| Shortcut | Action |
| --- | --- |
| ⌘N or ⌘O | Add project folders |
| ⌘F | Focus project search |
| Escape in search | Clear search and leave the field |
| ⌘= or ⌘+ | Zoom in |
| ⌘− | Zoom out |
| ⌘0 | Reset zoom to 100% |

## Background operation and data

A user LaunchAgent supervises the helper, which starts Amp and reconciles saved folders every two seconds, even when the manager is closed. The runner ID and startup workspace persist across launches.

- Missing folders stay saved and register when available. Removals remain pending until the CLI confirms them; offline removals finish on the next start. Amp may briefly restore a pending-removal folder before the helper unregisters it.
- **Running** means the local runner control interface responds, not that Amp's cloud service is reachable. Use **Runner Settings → Open Logs** to investigate failures.
- Manage this runner's folders through the app: external CLI additions are not tracked, and external removals are reasserted when the helper restarts. Other runners are not managed by this app.
- **Registration is not a filesystem sandbox or access revocation.** Amp runs with your user permissions, and existing threads may retain access to removed folders. macOS may request permission for protected locations.
- Amp also serves its startup directory. The app uses a dedicated empty `Workspace` folder rather than your home directory or its configuration directory.

Data lives in `~/Library/Application Support/AmpRunner/`:

| Path | Purpose |
| --- | --- |
| `configuration.json` | Runner ID, Amp executable, folders, and login preference |
| `status.json` | Registration state and helper heartbeat |
| `runner.log` | Helper and runner output; no automatic log rotation |
| `Workspace/` | Amp's startup directory |
| `com.local.AmpRunner.service.plist` | LaunchAgent when start at login is off |

With **Start at login** enabled, the plist lives in `~/Library/LaunchAgents/` instead. Enabling it while stopped schedules startup for the next login; it does not start the runner immediately. macOS may require background-item approval in System Settings. Theme and zoom are stored separately in macOS user defaults.

## Update or uninstall

**Stop the runner before moving, rebuilding, or deleting the app.** After moving or rebuilding, reopen the complete app bundle and start it again.

To uninstall, stop the runner and delete the app. You can retain its Application Support data for reinstall. If the app cannot open, stop its service manually:

```sh
launchctl bootout "gui/$(id -u)/com.local.AmpRunner.service"
```

Then remove `~/Library/LaunchAgents/com.local.AmpRunner.service.plist` if present to prevent startup at login. Do not delete your project folders.

## Development

Open `Package.swift` in Xcode. `RunnerCore` owns configuration, CLI execution, registration, and launchd integration; `AmpRunner` is the SwiftUI app; `AmpRunnerService` is the background helper. Use the complete app bundle to run the service.

```sh
swift test
/usr/bin/python3 scripts/smoke-test.py
```

The smoke test builds the helper and uses a disposable launchd job, fake Amp executable, and temporary folders. It checks registration, restart, failed removal/retry, child cleanup, and stopping without contacting Amp or changing real registrations. It requires a logged-in macOS GUI session. Real Amp connectivity and logout/login need manual checks.

For visual previews, quit the manager first, then open one state at a time:

```sh
open "dist/Amp Runner.app" --args --preview
# Quit the preview before opening the populated state.
open "dist/Amp Runner.app" --args --preview-populated
```

Previews use sample data without changing runner configuration or starting a service. Preview zoom is not saved; theme selection still updates the app's appearance preference.

App and menu-bar artwork lives in `Resources/AppIcon.svg` and `Resources/AmpRunnerMenu.svg`. Generated ICNS/PDF assets are included, so normal builds need no graphics tools. After editing the SVGs, regenerate them before rebuilding the app:

```sh
brew install librsvg # One-time prerequisite for asset regeneration
bash scripts/build-icons.sh
```
